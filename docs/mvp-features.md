# MVP 핵심 기능

---

## 1. 기존 원고 업로드 → 세계관 지식 그래프 구축 기능

### 흐름

작가가 전체 원고(예: 100화)를 한 번에 업로드하면, 서버는 이를 화 단위로 파싱해 저장하고 LLM 분석 파이프라인을 트리거한다.

### LLM 분석

LLM은 원고 전체를 분석해 등장인물, 주요 사건, 사물을 식별하고 이들 사이의 관계를 추론한다. 이후 추론한 관계를 Graph DB에 저장하기 위한 쿼리(Cypher 등)를 동적으로 생성한다.

```
(리온: 인물) -[보유]→ (마력: 능력)
(3화: 사건) -[유발]→ (마력_상실: 상태변화) -[대상]→ (리온: 인물)
(리온: 인물) -[소속]→ (마법사_길드: 조직)
```

### 저장 구조

- **Graph DB**: 인물·사건·사물 노드와 그 사이의 인과·소속·상태변화 등 관계 엣지. 충돌 감지와 관계 탐색의 핵심 저장소.
- **Vector DB**: 원고 원문을 청크 단위로 임베딩 저장. Graph 탐색만으로 컨텍스트가 부족할 때 원문 구절을 보조적으로 retrieve하는 용도.

### 결과 시각화

분석이 완료되면 구축된 지식 그래프를 작가에게 시각화해서 제공한다.

## 2. 신규 회차 업로드 → 설정 오류 탐지 기능

### 흐름

작가가 새로 작성한 회차를 업로드하면 검증 파이프라인을 실행된다.

### LLM 분석 및 Graph 탐색

LLM이 신규 회차에서 주요 인물·사건·사물을 추출하고, 이를 기준으로 Graph DB에 쿼리를 생성해 관련 노드와 엣지를 retrieve한다. 한 번의 쿼리로 충분한 정보가 확보되지 않으면 추가 쿼리를 반복해 필요한 관계 정보를 모두 가져온다. 

관련 컨텍스트가 충분히 모이면 LLM이 신규 회차의 내용과 기존 세계관을 대조해 설정 오류 여부를 판단한다.

### 오류 탐지 결과 처리

설정 오류가 발견되면 두 가지 수정 방향을 함께 제시한다.

- **신규 회차 수정안**: 기존 세계관에 맞게 새 회차의 해당 부분을 고치는 방향
- **기존 원고 수정안**: 반대로 새 회차의 설정을 밀고 가야 한다면, 기존 몇 화의 어떤 설정이 충돌하는지 명시하고 수정이 필요한 지점을 함께 제안

작가는 이 두 방향 중 하나를 선택할 수 있도록 한다.
