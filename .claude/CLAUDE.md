# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 레포지토리 목적

이 레포지토리는 **장편 소설 작가를 위한 AI 기반 스토리 엔지니어링 플랫폼**의 기획 문서를 작성·관리하는 공간이다. 코드가 아닌 PRD, 아키텍처 설계서, 사용자 플로우, KPI 등의 산출물을 생산한다.

핵심 기획 자료 원문: `.claude/docs/references.md`

## 제품 개요

**제품명(가칭):** LoreKeeper  
**부제:** 소설 작가를 위한 세계관 관리 및 설정 충돌 사전 감지 솔루션  
**슬로건:** "소설 검사기가 아닌, 세계관을 이해하는 코어 엔진을 먼저 구축하고, 설정 검사·템플릿 마켓·창작 어시스턴트를 무한히 확장하는 스토리 엔지니어링 플랫폼"

### 핵심 문제

장편 연재 작가의 설정 오류(모순)를 **사전(Proactive)**에 감지하고, 레트콘(Retcon) 시 과거 에피소드 전체에 미치는 **파급 효과(Ripple Effect)**를 양방향 추적한다.

### 사용자 핵심 플로우

| 단계 | 이름 | 핵심 행동 |
|------|------|-----------|
| Phase 1 | Onboarding & Ingestion | 원고 업로드 → 지식 그래프(Knowledge Graph) 자동 구축 + 수동 설정 등록 |
| Phase 2 | Drafting & Detection | 신규 원고 업로드 → RAG 파이프라인으로 설정 충돌 경고 |
| Phase 3 | Retcon / Ripple Effect | A루트(원고 수정) 또는 B루트(레트콘 강행 + 영향 에피소드 역추적 리포트) |

### 핵심 기술 키워드

- **Knowledge Graph** — 인물·사건·배경 간 인과관계 맵핑 (LLM Wiki 패턴)
- **RAG 파이프라인** — Elasticsearch(키워드/요약 검색) + WAS(인과관계 추론) → LLM 컨텍스트 조합
- **EDA / Kafka** — B루트 파급 효과 역추적은 비동기 이벤트 처리
- **DDD** — '원고 컨텍스트'와 '검증/추적 컨텍스트'를 분리 설계

### BM 로드맵

1. **MVP** — 설정 충돌 선제 감지 (리텐션 확보)
2. **확장 1** — 장르별 유료 템플릿 마켓 (무협 문파·무공, 판타지 마법 서클 등)
3. **확장 2** — 인터랙티브 RAG 대화 검색 + 플롯 보조 (구독 모델)

## 기획 문서 구조

기획 문서 작성 시 아래 목차 구조를 따른다.

```
# 목적 및 필요성
  ## 문제인식
  ## 기획의도

# 프로젝트 개요
  ## 프로젝트 소개
  ## 주요 기능
  ## 시장분석
  ## 시스템 구성도
  ## 개발환경
  ## AI 활용 전략

# 프로젝트 수행 방안
  ## 팀 구성 및 역할
  ## 멘토 구성 및 역할
  ## 추진 일정
  ## 수행 방법
  ## 예상문제 및 해결방법

# 결과물 및 기대효과
  ## 결과물 형태
  ## 결과물 활용방안
  ## 기대효과
```

## 문서 작성 원칙

- 모든 기획 문서는 한국어로 작성한다.
- 기술 용어(RAG, LLM, Kafka, DDD 등)와 코드·명령어는 영어 원문을 유지한다.
- 추측이나 가정(assumption)은 `> 가정:` 블록으로 명시한다.
- references.md의 핵심 논리(설득 포인트)를 문서 작성 시 근거로 적극 활용한다.
- 시장 규모, 사용자 통계, 기술 벤치마크 등 객관적 지표를 제시할 때는 반드시 출처(기관명, 보고서명, 발행연도, URL)를 함께 표기한다.
- 출처 표에는 나무위키·Wikipedia 등 불특정 다수가 편집 가능한 문서를 포함하지 않는다. 해당 문서는 조사 참고용으로만 활용하고, 출처 표에는 공신력 있는 기관 보고서·언론 기사·공식 사이트만 등재한다.
- 근거 데이터 조사 시 웹 검색을 적극 활용하여 최신 수치와 신뢰할 수 있는 자료를 확보한다.
