# Fact Checker Skill

## 워크플로우

1. 대상 파일을 읽는다. 경로가 명시되지 않은 경우 `docs/` 폴더의 .md 파일 목록을 확인하고 사용자에게 선택을 요청한다.
2. **출처 목록 추출**: 문서 내 출처 표, 각주, 인라인 링크에서 검증 대상 클레임과 출처 쌍을 추출한다.
3. **출처 실재 확인**: 웹 검색으로 각 출처(기관, 보고서, 기사)가 실제 존재하는지 확인한다.
4. **수치·주장 대조**: 출처에서 확인한 실제 데이터와 문서 기재 내용을 비교한다.
5. **논리 흐름 검증**: 출처 데이터로부터 결론을 도출하는 과정에 비약이 없는지 확인한다.
6. **파일 수정**: 오류 또는 문제 발견 시 Edit 도구로 직접 수정한다.
7. **검증 결과 보고**: 아래 **보고 형식**으로 요약한다.

## 검증 기준

### 1. 출처 실재성
- URL이 실제로 접근 가능하고 표기된 기관·보고서가 존재하는가
- 기관명·보고서명·발행연도가 정확한가
- 나무위키·Wikipedia 등 불특정 다수 편집 가능 문서를 공식 출처로 표기하지 않았는가

### 2. 수치 정합성
- 출처에 명시된 수치와 문서 기재 수치가 일치하는가
- 단위·기준연도·조사 범위가 출처와 동일한가
- 여러 출처의 수치를 합산·재계산했을 때 논리적으로 타당한가

### 3. 논리적 비약
- 출처 데이터(A)에서 결론(B)을 도출할 때 중간 근거가 충분한가
- 출처가 제시하지 않은 해석·전망을 사실처럼 서술하지 않았는가

### 4. 내부 일관성
- 문서 내 여러 섹션 간 수치·주장이 서로 모순되지 않는가
- 동일 데이터를 다른 섹션에서 다르게 표기하지 않았는가

## 수정 원칙

| 상황 | 처리 방법 |
|------|----------|
| 출처 URL이 잘못됨 (기관·보고서는 실재) | URL을 올바른 URL로 수정 |
| 수치가 출처와 다름 | 출처의 정확한 수치로 수정 |
| 출처가 존재하지 않음 | 해당 클레임 앞에 `> 가정:` 블록 삽입, 출처 셀을 `-`로 표기 |
| 논리적 비약 발견 | 해당 문장 뒤에 `> 가정:` 블록으로 비약 사실 명시 |
| 검증 불가(유료 보고서 등) | `> 가정:` 블록으로 검증 한계 명시, 수치는 유지 |

- 검증이 완료된 내용은 수정하지 않는다.
- 작성자의 해석·서술 방향은 유지하되, 사실과 다른 부분만 수정한다.
- 기술 용어(RAG, LLM, Kafka 등)는 팩트체크 대상이 아니다.

## `> 가정:` 블록 삽입 형식

```markdown
> 가정: [기관명] [보고서명]을 직접 확인하지 못했습니다. 제시된 수치([값])는 검증되지 않은 상태입니다.
```

## 보고 형식

```
## 팩트체크 결과: <파일명>

### 출처 확인 (<N>건 검증)
| # | 출처 | 확인 결과 | 비고 |
|---|------|----------|------|
| 1 | 기관명, 보고서명, 연도 | 확인됨 / 수정됨 / 가정처리 | 수정 내용 또는 사유 |

### 수치 대조 결과
| # | 클레임 | 문서 기재값 | 출처 실제값 | 처리 |
|---|--------|------------|------------|------|

### 논리적 비약 검토
| # | 위치(섹션) | 비약 내용 | 처리 |
|---|-----------|----------|------|

### 종합 판정
- 검증 완료: N건
- 수정됨: N건
- 가정 처리: N건
- 검증 불가: N건
```

이슈가 없으면: `문서 내 출처와 주요 수치에서 정합성 문제를 발견하지 못했습니다.`
