# risk-analysis

기획 문서의 "예상문제 및 해결방법" 섹션을 표 형식으로 작성한다.

## 작업 순서

1. `.claude/CLAUDE.md`와 `docs/` 폴더의 기존 문서를 읽어 서비스의 핵심 기능, 기술 스택, 추진 방식을 파악한다.
2. 아래 구분과 작성 기준에 따라 예상 문제점과 해결방안을 도출한다.
3. 결과물을 `docs/risk-analysis.md`에 저장한다.

## 구분 기준

- **개발 측면**: 기술 구현 난이도, LLM·Graph DB·RAG 등 핵심 기술의 정확도·성능 문제, 시스템 안정성
- **프로젝트 관리 측면**: 일정 지연, 팀 협업, 스코프 관리, 커뮤니케이션 문제
- **상용화 측면**: 사용자 확보, 수익화, 경쟁 서비스 대응, 서비스 운영 비용
- **기타**: 비용(API 비용 등), 저작권·법률·정책 이슈 등 필요 시 기재

각 구분마다 2개 이상의 문제점을 도출한다. 기타 항목은 해당 사항이 있을 때만 포함한다.

## 출력 형식

```markdown
# 예상문제 및 해결방법

| 구분 | 문제점 | 해결방안 |
|------|--------|----------|
| 개발 측면 | ... | ... |
| 개발 측면 | ... | ... |
| 프로젝트 관리 측면 | ... | ... |
| 프로젝트 관리 측면 | ... | ... |
| 상용화 측면 | ... | ... |
| 상용화 측면 | ... | ... |
| 기타 | ... | ... |
```

## 작성 기준

- 문제점은 구체적이고 현실적인 시나리오로 작성한다.
- 해결방안은 실행 가능한 기술적·운영적 대안을 제시한다.
- 모든 내용은 한국어로 작성하되, 기술 용어(LLM, RAG, Kafka 등)는 영어 원문을 유지한다.
- 서비스 특성(Knowledge Graph 기반 설정 충돌 감지, Ripple Effect 역추적)을 반영한 문제점을 우선 도출한다.
