# project-method

기획 문서의 "프로젝트 수행방법 > 추진방식" 섹션을 작성한다.

## 작업 순서

1. `.claude/CLAUDE.md`와 `docs/` 폴더의 기존 문서(PRD, MVP-scope 등)를 읽어 서비스의 핵심 기능과 기술 스택을 파악한다.
2. 파악한 내용을 바탕으로 아래 작성 기준에 따라 추진방식을 작성한다.
3. 결과물을 `docs/project-method.md`에 저장한다.

## 작성 기준

- 핵심 기능 각각에 대해 번호 순서로 작성한다.
- 각 항목은 **"기능명: 구현 방식 서술"** 형태로 시작한다.
- 구현 방식은 사용 기술(API, 라이브러리, 모델 등)과 동작 원리를 구체적으로 포함한다.
- 배포 이후 개선 계획이 있는 경우 해당 내용도 함께 서술한다.
- UI/UX 및 디자인, 유저 확보 방안, 사용자 피드백 수집, 기술 습득 노력 등은 기능 항목과 별도로 마지막에 서술한다.

## 출력 형식

```markdown
# 수행방법

## 추진방식

1. [기능명]: [사용 기술과 동작 원리 서술. 배포 후 개선 계획이 있는 경우 포함.]

2. [기능명]: ...

...

[UI/UX 및 디자인, 유저 확보, 피드백 수집, 기술 습득 등 부가 항목]
```

## 예시 (참고용)

```
1. 유튜브 플레이리스트를 기반으로 한 학습 영상 검색·추천: 검색 키워드를 바탕으로
YouTube Data API를 사용해 유튜브의 '좋아요' 수, 조회수를 기반으로 강의를 추천한다.
배포 이후 서비스 사용자의 후기 및 평점 데이터를 확보한 후 추천 기능을 보강한다.

2. 요약본 제공: youtube-transcript-api, STT(Speech-to-Text) 모델(AWS Transcribe,
OpenAI Whisper 등)을 사용해 자막을 생성한다. 추출된 자막을 토대로 LLM을 사용하여
요약본을 생성한다.
```

## 주의사항

- 모든 내용은 한국어로 작성한다.
- 기술 용어(RAG, LLM, Kafka, Spring Boot 등)는 영어 원문을 유지한다.
- 문장은 `~한다` 체로 끝맺는다.
- 임의로 기능을 추가하지 않고, 파악한 서비스 범위 내에서만 작성한다.
