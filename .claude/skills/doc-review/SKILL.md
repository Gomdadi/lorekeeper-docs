# Doc Reviewer Skill

## 워크플로우

1. 대상 파일을 읽는다. 경로가 명시되지 않은 경우 `docs/` 폴더의 .md 파일 목록을 확인하고 사용자에게 선택을 요청한다.
2. 아래 **검토 기준**에 따라 오류와 개선 사항을 분석한다.
3. Edit 도구로 파일을 직접 수정한다.
4. 수정 사항을 **변경 요약** 형식으로 보고한다.

## 검토 기준

### 1. 맞춤법 및 문장 부호
- 한글 맞춤법·띄어쓰기 오류
- 문장 부호 오용(쉼표·마침표·괄호·따옴표 위치)
- 불필요한 중복 조사(~을/를, ~이/가 중복)

### 2. 어휘 선택
- 어색하거나 부정확한 단어 사용
- 지나치게 구어적이거나 격식에 맞지 않는 표현
- 기술 용어 오기재(LLM, RAG, DDD 등 영문 용어는 원문 그대로 유지)

### 3. 문장 구조
- 주어·서술어 불일치 또는 생략으로 인한 의미 불명확
- 과도하게 긴 문장(한 문장이 3개 이상의 절로 구성되면 분리 고려)
- 피동 표현 남용

### 4. 논리적 흐름
- 단락 간 인과관계·순서 불일치
- 앞뒤 서술이 모순되는 경우
- 상관관계를 인과관계로 단정하는 서술
- 일부 사례를 전체로 과도하게 일반화하는 서술
- 중복 서술(같은 내용이 다른 단락에 반복)

### 5. 용어 일관성
- 동일 개념을 문서 내에서 다른 단어로 혼용(예: "사용자" vs "유저")
- 영문 약어 표기 불일치(예: "Knowledge Graph" vs "지식그래프" 혼용)

## 수정 원칙

- 의미가 바뀌는 수정은 하지 않는다. 작성자의 의도를 보존하며 표현만 교정한다.
- 기술 용어(RAG, LLM, Kafka, DDD, Knowledge Graph 등)는 영문 원문을 유지한다.
- `> 가정:` 블록은 내용을 수정하지 않는다.
- 표(table) 구조는 유지하되 셀 내용만 교정한다.
- 마크다운 서식(헤딩 레벨, 표, 코드 블록)은 변경하지 않는다.

## 변경 요약 형식

수정 완료 후 아래 형식으로 보고한다.

```
## 검토 결과: <파일명>

### 수정된 항목 (<N>건)
| # | 위치(섹션) | 유형 | 수정 전 | 수정 후 |
|---|-----------|------|--------|--------|
| 1 | ## 섹션명 | 맞춤법 | 원문 | 수정문 |

### 수정 없이 확인된 사항
- (없으면 생략)
```

오류가 없으면: `파일에서 검토 기준에 해당하는 오류를 발견하지 못했습니다.`
